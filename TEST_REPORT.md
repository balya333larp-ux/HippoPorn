# Проверки Cloudflare-сборки

## Выполнено локально

Runtime: Miniflare / workerd, SQLite Durable Objects, Node.js compatibility. Это runtime Cloudflare, а не имитация сервера на Node.js.

- Static assets: index.html, JS/CSS и игровые ресурсы доступны; /health и /info возвращают корректную сборку 490; /ws без upgrade возвращает 426; data.json не опубликован.
- Три независимых WebSocket-клиента: вход с постоянным токеном, общая публичная комната, снимки движения, чат, выстрелы, попадания и все пять видов гранат.
- Друзья: заявка/принятие, сохранение профиля и списка друзей, переподключение с тем же кодом.
- Приватная комната: неверный пароль отвергается; приглашённый игрок входит по приглашению.
- Принудительная выгрузка Durable Object с WebSocket hibernation: после реконструкции сохранены активные соединения, комнаты и обмен сообщениями.
- Достижение лимита убийств, победитель, отложенный перезапуск через 8 секунд и ротация Depot → Abbey.
- Два независимых Chromium-контекста открывают настоящий клиент из Worker, автоматически подключаются, создают/находят общую комнату и видят удалённого игрока.
- Между игровыми клиентами прошли HE/Smoke/Flash/Molotov/Decoy: урон, дым, ослепление, огонь и ложный звук. Отдельно проверен No Flash у получателя. Неправильный вид гранаты и чрезмерная скорость не передаются.
- JavaScript-ошибок в браузерном сетевом тесте не зафиксировано.
- Проверочная сборка deploy --dry-run прошла: корректны привязки HippoHub/HIPPO_HUB, ASSETS, миграция SQLite и импорт node:crypto.

## Что не проверено

Пакет НЕ опубликован в пользовательский аккаунт Cloudflare: для этого пользователь должен подключить свой GitHub-репозиторий в панели. Нет публичной проверенной ссылки. Не проверялись пользовательские Cloudflare-квоты, реальная задержка по Интернету, физический GPU или высокая нагрузка. Корректная локальная сборка не гарантирует, что Git-доступ/проверки конкретного аккаунта уже настроены.

## Архитектура

Нет постоянного интервала, удерживающего хаб в памяти. Игровой трафик обновляет счёт не чаще раза в секунду; один durable alarm отслеживает ближайшее окончание/перезапуск матча. Комнаты и социальные изменения сохраняются при управляющих событиях, а не на каждом снимке движения. Профили хранят только привязку к хешу токена, не сам токен. Совместимость с прежним клиентским протоколом 490 сохранена.
